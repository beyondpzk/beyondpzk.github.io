# GuideNav：纯视觉公里级导盲导航的 VT&R 技术解析

> **论文**：GuideNav: User-Informed Development of a Vision-Only Robotic Navigation Assistant For Blind Travelers
> **作者**：Hochul Hwang, Soowan Yang, Jahir Sadik Monon, Nicholas A Giudice, Sunghoon Ivan Lee, Joydeep Biswas, Donghyun Kim (UMass Amherst, DGIST, UMaine, UT Austin)
> **发布时间**：2025-12-05
> **会议**：HRI 2026 Systems Track (Honorable Mention)
> **arXiv**：https://arxiv.org/abs/2512.06147
> **项目代码**：github.com/guidedogrobot-navigation/GuideNav

## 一句话总结

GuideNav 是首个纯视觉 VT&R（Visual Teach-and-Repeat）导盲导航系统，仅靠单个 RGB 摄像头即可在公里级室外路线上安全引导视障人士行走，不依赖 GPS、LiDAR、深度传感器和 SLAM 度量地图，在 HRI 2026 上获得 Honorable Mention。

## 动机：为什么选 VT&R 而非 SLAM/GPS

GuideNav 的研究团队提出传统导航方案在导盲场景中的结构性缺陷：

| 传统方案 | 导盲场景中的问题 | GuideNav 的策略 |
|---------|-----------------|---------------|
| LiDAR | 成本高、功耗大；在雨雪雾中点云退化；对透明障碍物失效 | 纯 RGB 摄像头 |
| GPS | 城市峡谷、树荫下信号丢失；米级精度无法区分人行道与车道 | 视觉位置识别，不依赖卫星 |
| SLAM 度量地图 | 需专业工程师建图；地图维护成本高；缺乏语义信息 | 拓扑地图，普通人牵机器人走一圈即可 |
| 深度相机 | 室外强光下深度图质量差；有效距离有限 | Reloc3r 网络从 RGB 回归位姿 |

这一取舍的背后是人因研究的支撑——团队访谈了 26 名导盲犬使用者、4 名白手杖使用者、9 名训练师，累计观察 15 小时以上导盲犬辅助行走过程。核心发现：视障人士日常出行高度依赖固定路线，导盲犬本身的训练方式就是示教-重复，因此 VT&R 范式天然匹配用户需求。

## 技术架构

GuideNav 的系统架构分为示教阶段和重复阶段，核心是一个由拓扑地图、视觉位置识别、相对位姿估计和非线性反馈控制构成的模块化管线。

### 拓扑地图生成：从视频流到关键帧图

示教阶段，机器人记录图像流，用 DINOv3 编码每帧为全局描述符。自适应选择器同时考虑最小时间间隔、外观多样性、轨迹进度三个约束来提取关键帧。1 公里行程的拓扑地图仅占约 24 MB。

### 视觉位置识别（VPR）

使用 CosPlace 模型编码当前观测为 512 维描述符，通过余弦相似度在拓扑地图中检索最相似关键帧。信念更新机制以 Markov 链式约束强制时间一致性，降低感知混叠和跳帧误匹配。

### 相对位姿估计：Reloc3r

Reloc3r-512 网络输入当前图像和子目标图像对，输出相对 SE(2) 变换。纯 RGB，不依赖深度信息，对光照变化和场景变化具有更强鲁棒性。在 Jetson AGX Orin 上以 FP16/INT8 混合精度 5Hz 实时推断。

### 非线性反馈控制

从相对位姿计算线速度和角速度，采用 Lyapunov 稳定性设计确保收敛。不包含专用局部规划器——VT&R 的本质是沿记忆的路径走。

## 硬件与系统实现

| 组件 | 规格 |
|------|------|
| 机器人本体 | Unitree Go2 四足机器人 |
| 摄像头 | Intel RealSense D435i，仅用 RGB 流 |
| 计算平台 | NVIDIA Jetson AGX Orin |
| 交互接口 | 刚性挽具把手，用户与机器人刚性连接 |
| 运行频率 | 5 Hz 感知-决策-控制闭环 |

系统完全独立、无系绳，不需要云端计算和 RTK-GPS 基站。

## 实验验证

### 长距离野外测试

在 5 种不同室外环境（校园、居民区、公园、商业区、混合地形）中完成公里级路径跟随，示教和重复阶段之间存在显著场景变化（光照、动态障碍物）。

### 视障用户实地研究

招募 3 名资深导盲犬使用者和 1 名训练师进行盲测：

| 参与者 | 路线 | 距离 |
|--------|------|------|
| H01 | 停车场往返图书馆 | 短距离 |
| H02 | 家到公交站、餐厅往返美术馆 | 中等距离 |
| H03 | 家往返教堂 | 单程超 1 km，往返 2.02 km |

核心指标：

| 指标 | 结果 |
|------|------|
| 总导航距离 | 4940 m |
| 转向成功率 | 46/46 = 100% |
| 人工干预 | 仅 6 次，主要为避让复杂突发障碍 |
| 碰撞 | 1 次，被地面线缆缠住腿部 |

### 用户体验评估

视障用户 NASA-TLX 工作负荷极低（全部维度低于 6/20），SUS 可用性评分 H01 达 92.5、H03 达 95.0。专业训练师评分 52.5，因以真实导盲犬标准衡量，指出机器人动作略显生硬。

## 总结

GuideNav 是纯视觉 VT&R 导航在导盲场景中的里程碑式验证。它将导航问题从几何定位重新定义为视觉记忆检索——不是问我在哪里，而是问我现在看到的画面最像我曾经记住的哪一帧——在不依赖昂贵传感器和精确地图的情况下，仍能安全可靠地引导视障人士完成日常通勤。

其局限性在于：无局部规划器、拓扑地图无法与全局坐标对齐、需要为每条新路线单独示教、不支持开放语义导航。这些恰好是后续 ABot-N0、ABot-World 和 ABot-Claw 试图扩展的方向。

## 代码执行流程详解

更完整的参数说明、关键帧密度与地图扩展分析见[GuideNav 源码解读](/blog/2026/2026-09-29-guidenav-code-walkthrough)。

### 仓库结构与组件地图

```
GuideNav/
├── sensor/extract_data_two.py        # Teach：ROS2 记录图像流
├── topogen/gen_dinov3.py             # Teach：DINOv3 自适应关键帧选择（论文方法）
├── sensor/build_topomap.py           # Teach：里程计选帧的"朴素版"（非论文方法）
├── guidenav/navigate.py              # Repeat：主导航节点，唯一入口（~37KB）
├── guidenav/place_recognition/       # CosPlace 位置识别 + Bayesian 信念滤波
│   ├── extract_database.py           #   预计算地图描述符 → .h5
│   ├── feature_extractor.py          #   在线查询描述符
│   └── bayesian_querier.py           #   Markov 信念更新（默认）
├── guidenav/match_to_control/
│   ├── feature_match.py              #   Reloc3r 相对位姿估计封装
│   └── control.py                    #   (ρ,α,β) 非线性控制器
└── config/{robots.yaml, models.yaml}
```

三个外部模型的引入方式：CosPlace 网络代码直接复制进仓库（HLoc 风格接口，EfficientNet_B0 → GeM → Linear 1280→512），权重 `efficientnet_85x85.pth` 需从 Google Drive 手动下载；Reloc3r 需手动 clone 到 `guidenav/match_to_control/methods/reloc3r` 并应用 `third_party/reloc3r_load_images_in_memory.patch`（支持从内存传图像而非读文件路径），权重首次运行自动从 HuggingFace 下载（约 1.4GB）；DINOv3 必须本地 clone 并自带权重，否则回退 DINOv2（选出的关键帧与论文不同）。

### Teach 阶段：牵着走一圈 → 关键帧图

**第 1 步：记录数据**（`extract_data_two.py`）。ROS2 节点订阅 RealSense 的 RGB topic（深度与里程计可选，论文未使用），每帧以时间戳命名存 PNG：

```bash
python sensor/extract_data_two.py --output-dir ./data/teaching_run
# 输出: teaching_run/d435_color/*.png (+ depth/ + odom.csv 可选)
```

**第 2 步：DINOv3 自适应关键帧选择**（`topogen/gen_dinov3.py`）：

```bash
python topogen/gen_dinov3.py --input ./data/teaching_run/d435_color \
    --output ./data/topomap_raw --dinov3-repo /path/to/dinov3 --weights dinov3_vitl16.pth
```

每帧过 `dinov3_vitl16`（Resize 256 → CenterCrop 224 → ImageNet 归一化），特征 L2 归一化。论文的"三约束"对应 `multi_criteria` 选择器的四个条件：

| 论文约束 | 代码实现 |
|---|---|
| 最小时间间隔 | 距上一关键帧 ≥ **5 帧**才可能入选 |
| 外观多样性 | 与上一关键帧余弦相似度低于阈值，**或**与最近 5 个关键帧的最小相似度低于阈值 |
| 轨迹进度 | 距上一关键帧超过 **50 帧强制选入**（兜底防漏） |

阈值随地图规模自适应：关键帧 <20 个时 sim/diversity = 0.95/0.92（挑剔），20~100 时 0.93/0.90，≥100 时 0.91/0.88（保覆盖）。另有 `adaptive_threshold`、`diversity_buffer`、`temporal_spacing` 三种备选选帧策略。

**第 3 步：地图格式**。选出的帧重命名为 `0.png, 1.png, ... N.png`——**编号即路线顺序，这就是全部"拓扑"**，没有显式的边文件：

```
data/topomap/
├── 0.png  1.png  ...  N.png          # 单链关键帧，文件名解析为整数序号
└── global-feats-cosplace.h5          # 预计算的 CosPlace 描述符库（HLoc 格式）
```

`.h5` 由 `extract_database.py` 生成：每张图存一个 512 维 float32 描述符（L2 归一化）。导航首次运行时若缺该文件会现场提取（`--img-size` 必须与导航时一致，默认 `85 64`）。

Teach 阶段的本质：**不做任何几何重建、不算位姿、不建占据图**——只是把一条路线压缩成一串有代表性的画面 + 每帧一个 512 维检索指纹。

### Repeat 阶段：每个控制周期做什么

启动：

```bash
python guidenav/navigate.py --robot go2 --topomap-base-dir ./data -d topomap \
    --model-weight-dir model_weights --robot-config-path config/robots.yaml
```

节点订阅 `/d435i/color/image_raw`，发布 `/cmd_vel`。**循环由相机帧驱动**（无独立定时器，Go2 配置 4Hz），每帧执行一次 `navigate_one_step`，共 6 步：

**第 1 步：位置识别**——"我现在最像地图里的哪一帧"。CosPlace 将当前帧编码为 512 维描述符 `q`，与库中全部描述符算余弦距离 `d = √(2 − 2·qᵀgᵢ)`。

**第 2 步：Markov 信念更新**（`bayesian_querier.py`）——时间一致性滤波，防止感知混叠（两个相似路口跳错帧）：

- 初始化：`belief ∝ exp(−λ₁·d)`，其中 `λ₁ = ln(δ) / (Q97.5(d) − Q2.5(d))`，δ=10——按距离分布的 2.5%/97.5% 分位数自适应缩放，保证不同地图下判别力一致；
- 预测步：用长度 3 的全 1 核（窗口 `[-1, 2]`）对信念做 valid 卷积——编码"机器人每帧最多前进 0~1 个节点"的运动先验；
- 测量步：`belief *= exp(−λ₁·d(q, gᵢ))`，归一化；
- 取 `argmax(belief)` 为当前节点 `closest_node_idx`。

单次错误匹配会被后续观测稀释，因此系统不需要显式的"丢失定位恢复"模块。

**第 3 步：子目标选择**：

```python
subgoal_idx = min(closest_node_idx + lookahead, goal)   # lookahead 默认 1
```

永远朝"当前位置再往前一帧"的画面走；goal 默认是地图最后一帧。

**第 4 步：Reloc3r 相对位姿估计**（`feature_match.py`）。Reloc3r-512 输入（当前帧, 子目标帧）图像对，输出相对 SE(3)，提取 SE(2)：`x = t_z`（相机前向）、`y = −t_x`、`yaw = atan2(−R₀₂, R₂₂)`（度）。**关键细节：平移被归一化为单位长度**（`t /= ‖t‖`）——单目图像对无法恢复尺度，控制器拿到的 ρ 不是真实米制距离。若 `x < 0`（子目标已在身后）→ `subgoal_idx += 1` 重新估计，直到目标在前方或超出地图；估计失败 → 发零速。

**第 5 步：非线性控制器**（`control.vtr_controller`）。论文的 "Lyapunov 稳定控制" 对应经典 (ρ, α, β) 极坐标调节律，叠加启发式整形：

```
ρ = √(x²+y²),  α = atan2(y,x),  β = wrap(θ − α)

ρ < 0.08 且 |θ| < 5°  → 到达子目标，v = w = 0
ρ < 0.08              → 原地旋转对正朝向（v=0, w 限幅）
否则：
  v = v_max·(1 − e^(−0.8ρ))          # 指数整形：远处快、近处自动减速
  w = 0.8α − 0.4β                     # Lyapunov 航向律（k_α=0.8, k_β=−0.4）
  ρ < 0.5    → v 按 ρ/0.5 打折        # 末端减速
  |α| > 30°  → v 减半                 # 大转角先转后走
```

最后按机器人速度上限统一缩放（Go2：`max_v = 0.15 m/s, max_w = 1.0 rad/s`，导盲场景刻意很慢），发 `Twist` 到 `/cmd_vel`。

**第 6 步：终止与异常**。`closest_node_idx` 到达最后一帧 → `Goal reached!` 停车；每步 try/except，任何估计失败发零速；**没有专用局部规划器/避障**——VT&R 的哲学是"沿记忆的路径走"，安全依赖示教路线本身 + 人握刚性挽具在环内。

### 代码与论文表述的出入（读代码才发现的）

1. **平移无尺度**：Reloc3r 输出被归一化成单位向量，控制器的 ρ 不是米制距离——靠指数整形让"伪距离"也能稳定工作；
2. **"5Hz 闭环"没有定时器**，就是相机帧驱动，Go2 配置里实际写的是 4Hz；
3. **"轨迹进度"约束名不副实**：`gen_dinov3.py` 里只有"50 帧强制采样"，没有里程计意义上的进度约束（按 0.5m/15° 选帧的版本在未使用的 `build_topomap.py` 朴素构图器里）；
4. **死代码遗产**：GNM/ViNT 相关的 waypoint 模型参数（`--wp-model` 等）已移除但参数残留；`--use-smoothing` 未暴露为 CLI；Go2 SDK 不在仓库内，系统只发 `/cmd_vel`；
5. **不提供**示例 topomap、rosbag 与 DINOv3 权重（需自行申请）；CosPlace 权重在 Google Drive。

### 对室内 teach-and-repeat 改造的启示

- **可直接复用**：整个 Repeat 管线（CosPlace + Bayesian 滤波 + Reloc3r + 控制器）与室内外无关，搬到室内零改动；Teach 的 DINOv3 选帧同理；
- **需要调的参数**：室内关键帧更密时 `lookahead=1` 可加大；到达阈值（0.08 / 5°）与速度上限按机器人平台调整；
- **需要补的层**：地图目前是"无语义的单链"，"去厨房"这类语义目标需在关键帧上叠加 VLM 打标 + 检索层；分叉/回路需把单链升级为真正的图（加边文件 + 图搜索），替代现在的"序号 +1 即下一路段"。

### 对开箱即用式导航巡检的启示

GuideNav 给"开箱即用"下的定义，本质是**把导航从"几何问题"改成"记忆检索问题"**：不问"我在哪米、地图怎么建"，只问"我现在看到的画面最像我记住的哪一帧"。这是它所有开箱即用特性的根，也是移植到巡检时最该守住的一条。

**四个具体来源：**

1. **不建地图，只建"相册"**：一条路线压缩成一串关键帧，文件名编号就是路线顺序（这就是全部"拓扑"），每帧再算一个 512 维检索指纹。1 公里约 24 MB，没有占据图、位姿图、回环对齐。天然可编辑——删一张图等于删一段路，拼目录重编号等于拼路线。
2. **单 RGB 摄像头**：不依赖 GPS、LiDAR、深度、标定和 SLAM 度量地图，成本低、部署门槛低，室外强光下纯视觉反而比深度相机更稳。
3. **部署动作只剩两件**：牵着机器人沿路线走一圈 + 跑一个建图脚本。没有专业工程师建图、没有调参、没有标定。
4. **定位是全局检索而非递推**：CosPlace 拿当前画面和整张地图比对，机器人开机放在路线任意位置也能自动认出自己在哪一段，不需要对准起点——这天然解决了无人巡检"重启后怎么找回自己"的问题。

**直接映射到巡检的三样免费红利：**

- **关键帧图本身就是检查点列表**：teach 时给关键帧打标签（"3 号门""配电箱"），repeat 到达该节点就触发拍照/打卡/上传，检查点与路线共用同一数据结构；
- **关键帧天然是"基准图"**：变化检测时拿当前帧和对应关键帧对比（帧差/光流/DINOv2 特征距离）就能发现"原来没有的东西"，这是巡检相对固定摄像头监控的差异化价值；
- **巡检路线恰好是固定重复路线**：正是 VT&R 的甜区，和 GuideNav 最擅长的事天然匹配。

**但"开箱即用"只覆盖导航内核，不覆盖巡检业务本身。** 原版有五个硬缺口，这些地方不能继续偷懒：

- **避障是零**：导盲场景靠"人握刚性挽具"兜底，巡检把人拿掉后这是第一缺口。P0 的零改动做法是加一个 LiDAR `safety_node` 夹在 `/cmd_vel` 前做急停；
- **单链结构**：无环、无分支、无语义，多路线和环路要拆段或升级为图结构；
- **速度只有 0.15 m/s**，且 Reloc3r 平移被归一化成单位长度（没有真实尺度），要提速得先补尺度；
- **纯 RGB 夜间退化**；
- **每条新路线都要单独示教一次**。

地图更新上还有一个重要原则：**自动检测 + 人工确认，不要全自动写图**。系统分不清"停了三天的车"和"永久的新墙"，全自动更新会把临时变化误写成持久变化。

一句话总结这份启发：**开箱即用的本质是"把不可靠的几何重建换成可靠的视觉记忆"，但安全、语义、业务产出必须作为额外层显式补上——先跑通固定路线，再逐层加智能。**
