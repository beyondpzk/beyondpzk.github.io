# RegCache：视觉编码器激活量化需要前缀 Register

> **论文**：Activation Quantization of Vision Encoders Needs Prefixing Registers  
> **发布时间**：2025-10-06  
> **会议**：ECCV 2026  
> **arXiv**：https://arxiv.org/abs/2510.04547

## 一句话总结

RegCache 是一个免训练的视觉编码器量化插件：向 ViT 前缀注入“容易产生 outlier 但语义无意义”的 register token，把普通 token 的 outlier 吸收掉，从而让 8-bit、甚至 4-bit 激活量化更稳定。

## 动机

大规模预训练视觉编码器（CLIP、SigLIP 等）即使做 8-bit 量化也可能掉点，主要原因是 outlier token：

- 少量背景 patch token 会成为 attention sink；
- 这些 token 的幅值远大于普通 token；
- 一个 outlier 会把 per-tensor scale 撑大，压缩所有正常 token 的精度。

不同于 LLM 中 outlier 主要由少量通道产生，视觉编码器的 outlier 还和 token 位置、层级有关。

## 核心方法

### 1. Prefixing Registers

RegCache 在视觉 token 前加入“outlier-prone”的 register token。这些 token 故意承担 outlier 角色，使其他语义 token 不再产生极端激活。

### 2. Middle-Layer Prefixing

视觉编码器中的 outlier 不一定只在第一层出现。RegCache 观察视觉模型的行为后，在**中间层**也注入/缓存 prefix register，而不仅仅在最前端。

### 3. Token Deletion

对于已经不再需要的高幅值 token，RegCache 在推理时删除或替换，进一步抑制 outlier 对量化 scale 的影响。

## 关键结果

- 在 CLIP、SigLIP 等多种预训练视觉编码器上有效；
- 4-bit 低比特配置收益显著；
- 可作为插件叠加在其他量化方法之上；
- 能改善 VLM 视觉塔量化后的端到端精度。

## 部署视角

RegCache 对 VLM/视觉模型部署很有价值：

- 免训练，只修改推理时 token 序列；
- 可以与 PTQ4ViT、RepQ-ViT、QwT 等方法组合；
- 不需要修改预训练权重，适合快速上线；
- 特别适合 CLIP/SigLIP 视觉塔的低比特部署。

## 局限

- register 数量和位置需要按模型调；
- token deletion 会改变注意力/上下文长度，需要 kernel 支持；
- 对自监督模型（如 DINOv2）的 outlier 位置可能更分散，收益需验证。

## 总结

RegCache 给出了视觉编码器量化中一个反直觉但有效的思路：主动制造可管理的 outlier token，让正常 token 保持可量化。它是当前 VLM 视觉塔低比特部署中最值得关注的无训练插件之一。
