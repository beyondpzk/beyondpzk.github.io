# AutoInspect：面向长期自主工业巡检的足式机器人系统

> **论文**：AutoInspect: Towards Long-Term Autonomous Industrial Inspection
> **作者**：Michal Staniaszek, Tobit Flatscher, Joseph Rowell, Hanlin Niu, Wenxing Liu, Yang You, Robert Skilton, Maurice Fallon, Nick Hawes (Oxford Robotics Institute, UKAEA RACE)
> **发布时间**：2024-04-19
> **会议**：ICRA 2024 Workshop on Field Robotics, Journal of Field Robotics (accepted)
> **arXiv**：https://arxiv.org/abs/2404.12785

## 一句话总结

AutoInspect 是牛津机器人研究所与英国原子能管理局联合开发的完整工业巡检自主系统，在波士顿动力 Spot 上实现了持续数周无中断的自主导航、数据采集与异常检测。它把 SLAM、拓扑导航、任务调度和变化检测集成进一套 ROS 软件栈中，并在 JET 聚变反应堆等核设施中完成了真实部署。

## 系统总览

AutoInspect 是一个基于 ROS 的任务级自主系统，设计围绕以下四条核心需求展开：

1. 提供标准化接口，便于集成不同机器人的能力；
2. 能在最少量人工干预下长时间自主运行；
3. 对研究人员和工业伙伴友好、易于上手；
4. 适配不同机器人和硬件配置。

系统部署分两个阶段：先由操作人员遥控机器人走一圈完成 SLAM 建图和拓扑地图生成，之后机器人完全自主运行，按预定时间表或按需执行巡检任务。

## 硬件平台

| 组件 | 规格 |
|------|------|
| 机器人本体 | Boston Dynamics Spot |
| 传感器载荷（Frontier） | Hesai XT-32 LiDAR、3 路 Sevensense Alphasense 鱼眼相机、Bosch BMI085 IMU、NUC i7-1165G7（32 GB RAM） |
| 辅助载荷 | Spot CAM+IR（PTZ 可见光 + 热成像）、温湿度传感器、Kromek Sigma 50 Gamma 射线探测器 |
| 通信 | Rajant ES-1 工业级 mesh 网络节点 |
| 系统重量 | Frontier 载荷约 1.5 kg，传感器刚性固定，换机器人无需重新标定 |

AutoInspect 软件栈完全运行在 Frontier 载荷的 NUC 上，不依赖云端，mesh 网络仅用于操作员远程监控和任务下发。

## 建图与定位：VILENS SLAM

建图采用牛津自研的 **VILENS** 系统（融合 IMU、LiDAR 和 Spot 的腿里程计），包含两个核心模块：

- **VILENS Odometry**：对点云做运动补偿（补偿四足步态的颠簸），输出增量位姿和去畸变 LiDAR 扫描；
- **VILENS SLAM**：基于 iSAM2 因子图优化，用 ScanContext 描述子做回环检测。

本地化阶段，系统用 ICP 将当前点云配准到先验全局地图，以 2Hz 提供连续位姿估计。此外集成了 **LiSTA** 三维变化检测系统，通过对不同巡检批次中同一空间区域的点云做八叉树体素差分、RANSAC 地面过滤和欧氏聚类，输出对象级变化检测结果，直接告诉操作员"哪里多了或少了什么"。

## 拓扑自主系统：图导航 + 任务调度

AutoInspect 的自主层基于**拓扑地图**：

- 从 SLAM 位姿图自动生成初始拓扑图，再通过 RViz GUI 人工精修；
- 节点附带 3D 位置和检查点属性，边附带巡检动作类型；
- 路径用最短路径算法规划，遇障碍时自动重路由（暂时禁用阻塞边并重新计算）；
- 支持自定义边的遍历方式（如通过门、上楼梯），在遍历边同时执行特定动作（如拍摄沿途管道）。

**任务执行与调度**：

- 任务 = 在指定节点位置执行一个动作（拍照、测温、Gamma 采集等）；
- 任务 = 任意数量的有序任务，可自动用 TSP 求解器重排序以最短路径执行；
- 调度器支持固定排班（如每个工作日 11:00 和 15:00 执行），并包含系统监控——如电量过低则跳过预定任务，自动执行"返回充电站"任务。

**与机器人的接口**：通过 ROS actionlib 抽象，已在 Clearpath Husky、Toyota HSR、Hello Robot Stretch 和 Spot 上验证了跨平台能力。

## 长期部署验证

论文详细报告了两次数周级长期部署：

### RACE B1 测试设施（49 天）

| 指标 | 数据 |
|------|------|
| 部署时长 | 2023-07-18 至 2023-09-05，共 49 天 |
| 拓扑地图 | 37 个节点，其中 9 个检查点 |
| 巡检任务 | 每工作日 11:00 和 15:00，共 84 次任务 |
| 检查动作成功率 | 673/730 = 92.2% |
| 总里程 | 13.6 km，约 13 小时活跃任务时间 |
| 最长无中断运行 | 14 天 |
| 平均故障间隔（不含轻微干预）| 78 小时 |

暴露的典型 bug：长时间运行后 CPU 降频导致定位漂移，这种问题只有在长期部署中才会浮现。

### JET 聚变反应堆（35 天）

| 指标 | 数据 |
|------|------|
| 部署时长 | 2024-02-21 至 2024-03-27，共 35 天 |
| 拓扑地图 | 41 个节点，7 个检查点 |
| 巡检任务 | 每天 11:00 和 15:00，共 81 次任务 |
| 总里程 | 15 km，约 19.5 小时活跃任务时间 |
| 最长无中断运行 | 15 天 |
| 平均故障间隔（不含轻微干预）| 140 小时 |

JET 部署中集成了 Gamma 射线探测器。从同一位置拍摄的 60 张图像几乎完全一致，验证了长期部署中定位的重复精度。5 次致命故障全部源于同一个用户界面进程管理器 bug（已在实验室复现），核心 SLAM 和导航系统无一故障。

## 关键洞察

- **硬件抽象是长期自主的基础**：通过将建图、定位、导航、任务执行解耦为标准化接口，AutoInspect 已经迁移了 5 种机器人平台而不需要重写自主逻辑；
- **拓扑地图比度量地图更"可操作"**：操作员理解"走到节点 3 拍照"比理解"走到坐标 (15.2, -3.7)"容易得多，也更容易修改；
- **真正的鲁棒性问题只在长期部署中暴露**：RACE 部署中的 CPU 降频导致定位漂移、JET 部署中的 GUI 进程 bug 都是在实验室模拟中无法重现的问题。

## 总结

AutoInspect 不是一个算法论文，而是一个**系统工程报告**。它的贡献不在于提出新的路径规划器或 SLAM 算法，而在于把牛津机器人所多年积累的自主系统技术（VILENS SLAM、拓扑导航、任务调度、LiSTA 变化检测）整合成一套能在核电站、化工厂、矿山中连续工作数周的完整软件栈。对于从事工业巡检系统落地的团队来说，它的模块化设计哲学、长期部署日志和故障分析是非常实用的参考。
