# 户外长距离导航技术方案（专注高德集成与导盲场景）

> 参考高德"涂涂"智能导盲机器人与 ABot 全栈具身技术体系，设计一套纯户外长距离导航方案，深度集成高德地图能力，面向导盲、陪伴、配送等开放环境全自主行动场景。

---

## 一、产品定位与场景定义

### 1.1 参考产品：高德"涂涂"

高德"涂涂"是阿里巴巴旗下高德于 2026 年 4 月发布的首款具身机器人，核心特征：

- **形态**：四足机器人（类似 Unitree Go2）；
- **定位**：智能导盲犬，辅助视障人士户外出行；
- **能力**：开放环境下全自主行动，无需人工干预；
- **技术底座**：ABot 全栈具身技术体系（ABot-N 导航基座 + ABot-M 操作基座）。

### 1.2 目标场景

本方案聚焦**纯户外长距离导航**，不包括室内场景：

| 场景类型 | 示例 | 核心需求 |
|---|---|---|
| **导盲出行** | 从家到超市、从地铁站到公司 | 安全、可靠、社会合规 |
| **陪伴散步** | 公园、小区、商业街 | 舒适、避障、跟随 |
| **物品配送** | 从驿站到楼栋门口 | 精准、高效、抗干扰 |
| **紧急响应** | 从当前位置到求助地点 | 快速、稳定、可远程接管 |

### 1.3 核心挑战（纯户外）

| 挑战 | 具体表现 |
|---|---|
| **全局-局部割裂** | 高德路径是米级精度，无法直接指导机器人局部避障 |
| **社会合规复杂** | 必须走人行道、斑马线，避让行人、自行车、电动车 |
| **动态障碍密集** | 行人、车辆、外卖员、宠物等高频动态交互 |
| **天气光照变化** | 晴天、雨天、夜晚、逆光等视觉条件变化 |
| **长程依赖强** | 数公里导航需要持续跟踪全局进度，不能迷路 |

## 二、总体架构：高德深度集成 + 云边协同

### 2.1 系统架构

```
用户语音指令（"带我去家乐福"）
        ↓
[云端 Agentic Planner]
    ├── 高德 POI 搜索：找到最近家乐福
    ├── 高德路径规划：步行路线（人行道优先）
    ├── 高德实时路况：避开施工、拥堵路段
    ├── Topo-Memory：历史路径、已知障碍、用户偏好
    └── VLM 语义转换：高德路由 → 分段自然语言导航指令（路标锚定）
        ↓
[边缘 VLA 导航模型]
    ├── 视觉感知：人行道边界、斑马线、障碍物、红绿灯
    ├── 语言理解：局部指令（"沿人行道走到前方路口"）
    └── 航点生成：未来 5~8 个局部航点
        ↓
[Neural Controller + 安全层]
    ├── 实时避障：LiDAR/深度相机检测近距离障碍
    ├── 社会合规：强制走人行道、斑马线等待、行人避让
    ├── 速度控制：平滑加速/减速、紧急停止
    └── 地理围栏：禁止进入车行道、施工区、水域
        ↓
四足机器人运动执行
```

### 2.2 高德能力深度集成

不是简单调用高德 API，而是**将高德能力作为系统核心组件**：

| 高德能力 | 集成方式 | 作用 |
|---|---|---|
| **POI 搜索** | Planner 查询目标地点坐标和属性 | 确定导航终点 |
| **步行路径规划** | Planner 获取人行道级路径 | 全局路由 |
| **实时路况** | Planner 动态调整路径 | 避开施工/拥堵 |
| **电子围栏** | 安全层强制约束 | 禁止进入危险区域 |
| **AR 导航** | 可选：用户手机端可视化 | 人机协同确认 |
| **室内地图** | 可选：终点室内引导 | 最后几米衔接 |
| **语音交互** | 用户自然语言指令输入 | 意图理解 |

### 2.3 云边分工

| 功能 | 部署位置 | 延迟要求 | 说明 |
|---|---|---|---|
| 高德 POI/路径查询 | 云端 | 秒级 | 任务开始时调用 |
| Agentic Planner | 云端 | 秒级 | 任务拆分与重规划 |
| VLA 航点生成 | 边缘 | 500ms（2Hz） | 局部导航核心 |
| Neural Controller | 边缘 | 100ms（10Hz） | 实时控制 |
| 紧急避障 | 边缘 | <50ms | 安全底线 |
| 高德实时路况更新 | 云端 | 分钟级 | 长程导航中动态调整 |

## 三、数据引擎设计（纯户外导向）

纯户外长距离导航的数据策略与室内外混合导航有显著差异，需要**强化户外场景覆盖**和**社会合规标注**。

### 3.1 数据类型与规模

| 数据类型 | 用途 | 目标规模 | 获取方式 |
|---|---|---|---|
| **户外 PointNav** | 基础移动与避障 | 2M~3M | 仿真 + 真实 + 互联网视频 |
| **户外 VLN** | 语言指令跟随 | 1M~2M | 仿真 + 视频生成 |
| **社会导航** | 行人避让、社会合规 | 1M~2M | SocCity 仿真 + 真实标注 |
| **POI 导航** | 语义地点到达 | 1M~2M | 街景 + 视频生成 |
| **户外推理数据** | 空间推理、安全判断 | 1M~2M | 自动生成 + VLM 标注 |

### 3.2 户外 PointNav 数据采集

#### 仿真采集（城市环境）

- **场景**：
  - **SocCity**：动态虚拟城市（~3.4 km²），含车辆、行人、交通灯；
  - **CityWalker 仿真场景**：城市街道、路口、人行道；
  - **自建城市仿真**：基于真实城市 GIS 数据生成；
- **方法**：
  1. 在人行道导航图上采样起点和终点；
  2. A* 规划最短路径，强制走人行道；
  3. 加入**恢复轨迹**：偏离人行道后回正；
  4. 加入**动态障碍**：行人、车辆随机出现；
- **规模**：1.5M~2M 条。

#### 真实机器人采集

- **来源**：SCAND、HuRoN、Recon、CityWalker 遥操作数据；
- **筛选**：仅保留户外场景数据；
- **标注**：人工标注可通行区域（人行道、斑马线）、危险区域（车行道）；
- **规模**：300K~500K 条。

#### 互联网视频伪轨迹

- **来源**：第一人称城市行走视频（YouTube、Bilibili、抖音）；
- **方法**：
  1. **π3** 稠密 3D 重建；
  2. **MoGe** 尺度对齐；
  3. 语义分割：区分人行道、车行道、斑马线；
  4. 沿人行道采样导航样本；
- **规模**：1M~1.5M 条。

### 3.3 户外 VLN 数据采集

户外 VLN 与室内 VLN 差异很大：指令更依赖**路标、方向、距离**。

#### 仿真采集

- **场景**：城市仿真环境；
- **指令风格**：
  - "沿人行道往前走 200 米，到红绿灯路口右转"
  - "经过左边的便利店，继续走到公交站"
  - "穿过斑马线，沿商铺外侧走到地铁站入口"
- **生成方式**：
  1. 在高德/仿真地图中规划路径；
  2. 沿路径生成自然语言指令；
  3. 用 LLM 改写为多样化表达；
  4. 教师强制回放轨迹；
- **规模**：500K~1M 条。

#### 视频生成

- **方法**：参考 ABot-N0 的 POI-Goal 数据合成；
  1. 输入街景图像 + 目标 POI；
  2. 分割 + 深度 → 局部占用图 → A* 规划；
  3. **Wan2.1-I2V** 或类似模型生成第一人称导航视频；
  4. 从视频中采样轨迹；
- **规模**：500K~1M 条。

### 3.4 社会导航数据采集（核心）

社会导航是户外场景的最大挑战，也是"涂涂"导盲场景的安全底线。

#### SocCity 仿真

- **场景元素**：
  - 动态行人（不同速度、方向、密度）；
  - 车辆（汽车、公交车、电动车）；
  - 交通设施（红绿灯、斑马线、盲道、护栏）；
  - 静态障碍（共享单车、垃圾桶、施工围挡）；
- **标注**：
  - 层次化占用图：人行道 / 斑马线 / 车行道 / 绿化带 / 危险区；
  - 社会合规标注：是否礼让行人、是否遵守红绿灯、是否占用盲道；
- **训练方法**：**SAFE-GRPO**
  - 冻结 Brain，仅微调 Action Expert；
  - 奖励函数：社会合规 + 专家相似 + 平滑 + 效率；
  - 关键：让模型学会"物理可通行 ≠ 社会可接受"；
- **规模**：1M~2M 条。

#### 真实世界标注

- **来源**：城市监控、行车记录仪、机器人真实采集；
- **标注**：
  - 可通行区域多边形（人行道、斑马线）；
  - 动态障碍物轨迹（行人、车辆）；
  - 交通灯状态；
- **规模**：1.2M 张图像（ABot-N0 参考）。

### 3.5 POI 导航数据采集

POI 导航是"带我去家乐福"这类任务的核心。

#### 数据来源

- **高德 POI 数据库**：海量真实 POI 名称、类别、坐标；
- **街景图像**：高德/百度街景、用户上传；
- **视频生成**：Wan2.1-I2V 合成第一人称 POI 导航视频。

#### 标注

- **POI Grounding**：POI 名称 ↔ 入口像素坐标；
- **入口检测**：商铺门口、小区入口、地铁站入口；
- **最后几米路径**：从街道到 POI 入口的精确路径；
- **规模**：0.5M~1M 条。

### 3.6 户外推理数据采集

推理数据防止模型退化为"看到人行道就走"的条件反射。

| 子集 | 内容 | 规模 |
|---|---|---|
| 可通行区域分析 | 标注人行道、斑马线、危险区域多边形 | 1.2M |
| 社会导航 CoT | "红灯，必须等待"、"前方有行人，应减速绕行" | 0.8M |
| 交通灯识别 | 红绿灯状态与对应动作 | 0.3M |
| 天气/光照适应 | 雨天、夜晚、逆光场景判断 | 0.5M |
| POI Grounding | POI 名称与入口坐标对应 | 0.5M |

## 四、模型训练策略

### 4.1 三阶段训练（纯户外适配）

#### Phase 1：Cognitive Warm-up（认知预热）

- **数据**：户外推理数据（2M）；
- **目标**：学会识别可通行区域、交通灯、社会规范；
- **方法**：冻结视觉编码器，微调 LLM backbone；
- **输出**：具备户外安全推理能力的 Brain。

#### Phase 2：Unified Sensorimotor SFT（统一感觉运动微调）

- **数据**：户外 PointNav + VLN + POI + 社会导航轨迹（5M~8M）；
- **混入**：20% 推理数据回放，防止遗忘；
- **方法**：联合优化 AR Head 和 Flow Matching Action Head；
- **输出**：统一户外导航 VLA 模型。

#### Phase 3：SAFE-GRPO 社会合规对齐

- **数据**：SocCity 社会导航轨迹（1M~2M）；
- **方法**：冻结 Brain，仅微调 Action Expert；
- **奖励**：
  ```
  R = w_soc · R_social + w_exp · R_expert + w_sm · R_smooth + w_eff · R_eff
  ```
- **关键**：让模型内化"人行道优先、斑马线过街、礼让行人、红灯停"；
- **输出**：社会合规的户外导航模型。

### 4.2 模型选型

| 组件 | 推荐方案 | 说明 |
|---|---|---|
| **视觉编码器** | SigLIP-B/16（93M） | 边缘部署友好 |
| **语言骨干** | Qwen3-4B | 推理能力足够 |
| **动作头** | Flow Matching | 连续航点生成，多模态分布 |
| **Planner** | Qwen3-VL / GPT-4V | 云端任务拆分 |
| **安全层** | 规则系统 + 轻量 CNN | 独立于 VLA 的紧急避障 |

### 4.3 边缘部署优化

参考 ABot-N0 的 Jetson Orin NX 部署：

- **Token merging**：merge size=4，性能损失 <3%；
- **FP8 量化**：进一步压缩模型；
- **TensorRT**：端到端推理加速；
- **目标频率**：2Hz VLA + 10Hz 控制 + 50Hz 紧急避障。

## 五、安全设计（导盲场景最高优先级）

导盲场景对安全性要求极高，必须采用**多层安全冗余**。

### 5.1 五层安全体系

| 层级 | 机制 | 响应时间 | 作用 |
|---|---|---|---|
| **L1 地理围栏** | 高德电子围栏 + 本地地图 | 事前 | 禁止进入车行道、水域、施工区 |
| **L2 社会合规** | SAFE-GRPO 训练 | 500ms | 强制走人行道、斑马线等待 |
| **L3 实时避障** | LiDAR/深度相机 + Neural Controller | 100ms | 避开静态/动态障碍 |
| **L4 紧急停止** | 独立安全控制器 | <50ms | 碰撞前紧急制动 |
| **L5 人工接管** | 远程监控 + 紧急按钮 | 人工 | 极端情况人工介入 |

### 5.2 关键安全规则

- **人行道强制**：除非过马路，否则必须保持在人行道内；
- **斑马线过街**：只能在斑马线或过街天桥/地道过街；
- **红灯停**：交通灯红灯时必须停止等待；
- **行人优先**：检测到行人时必须减速或停止礼让；
- **盲道尊重**：不长时间占用盲道；
- **速度限制**：人行道 ≤1.5 m/s，拥挤区域 ≤0.8 m/s。

## 六、高德集成详细设计

### 6.1 任务启动流程

```
用户："带我去家乐福"
    ↓
1. 高德 POI 搜索：找到最近家乐福（坐标、入口、营业时间）
    ↓
2. 高德路径规划：步行路线（人行道优先，避开高架/高速）
    ↓
3. 高德实时路况：检查施工、拥堵、临时管制
    ↓
4. Planner 语义转换：全局路径 → N 段导航指令（路标锚定，如"沿人行道走到前方路口，过斑马线左转"）
    ↓
5. 边缘 VLA 以 VLN 模式逐段执行
    ↓
6. 每段完成后，Planner 更新进度，必要时重新查询路况
```

### 6.2 动态调整机制

- **路况变化**：高德推送施工/拥堵信息，Planner 重新规划；
- **用户偏好**：用户说"走河边那条路"，Planner 调整路径；
- **临时障碍**：边缘 VLA 检测到前方施工，上报 Planner，重新规划局部路径；
- **电量/体力**：机器人电量不足时，Planner 自动规划最近充电点。

### 6.3 人机协同

- **语音确认**：关键路口前，机器人语音询问"前方左转，确认吗？"；
- **手机 AR**：用户手机显示机器人视角和规划路径，可手动调整；
- **紧急呼叫**：机器人检测到用户跌倒或异常，自动呼叫紧急联系人。

### 6.4 Planner 局部目标精修：是模型还是规则？

**结论：是模型，不是规则。** ABot-N0 中并不存在一个独立的"精修模块"——局部目标精修就是 Agentic Planner（VLM）自身的能力，是它粗到细任务分解过程的一个环节。

#### 精修由谁完成

| 组件 | 形态 | 是否参与精修 |
|---|---|---|
| **Agentic Planner** | 独立 VLM（通用奖励模型，VLAC 闭环），云端部署 | ✅ 精修的主体 |
| ABot-N0 Actor | Qwen3-4B + Flow Matching，边缘部署 | ❌ 只接收精修后的子目标 |
| 安全层 | 规则系统 | ❌ 只做确定性约束 |

Planner 不是现成 VLM 的 zero-shot 调用，而是在大规模异构数据上训练过的**通用奖励模型**（General Reward Model），通过 prompt 切换 Policy（任务分解）/ Critic（完成评估）两种模式。它天然具备"看画面 + 理解意图 + 判断进度"的能力，局部目标精修正是这些能力的组合。

#### 精修如何发生

精修不是一个独立函数调用，而是 Planner CoT 推理的中间产物：

```
输入: 高德意图("沿人行道往东北约200m")
     + 粗略当前位置（米级误差可接受）
     + 当前视觉观测(人行道边界、障碍物、路口)
     + Topo-Memory 语义图层
        ↓ Planner VLM 视觉 grounding + 语义判断
输出: 路标锚定的语义导航指令
     "沿人行道走到第一个路口, 过斑马线右转"
```

**最终决策：采用语义指令方案，放弃坐标式精修。** 理由：

- **像人一样导航**：人类听"100 米后左转"就能执行，靠的不是坐标换算，而是语言指令 + 视觉路标的对齐能力——这正是 VLA 的 VLN 模式原生具备的能力（ABot-N0 已有 1.5M 条 R2R/RxR 训练轨迹打底）；
- **对定位误差天然鲁棒**："走到路口左转"不依赖任何具体经纬度值，高德米级误差完全可容忍；
- **GT 管线大幅简化**：坐标式精修 GT（6.5 节 A 类）整套不用做，语义指令 GT 直接复用 R2R/RxR 的成熟生成管线。

#### 语义方案没有消除的三件事

精修被**转移**而非消除，以下能力仍然是 Planner 的职责：

1. **分段与触发时机**：Planner 仍要决定把全局路由切成多少段、每段指令在什么时候下达——相当于导航 App 决定什么时候开口说"前方左转"；
2. **段推进的定位监控**：仍需全局定位判断"这一段是否走完"，但只用于触发下一段指令，**不进入控制环**，米级精度即可；
3. **失败重规划**：指令执行失败（路被堵、走错路口）时，Critic 发现异常并触发重新路由。

另外两个工程要点：

- **指令必须路标锚定，不要距离锚定**："走到前方路口左转"比"走 100 米左转"可靠——VLA 没有精确里程感，人其实也是靠看到路口才转的；
- **Planner 在这一步做的不是坐标换算，而是视觉 grounding + 语义判断**——把高德的路由意图翻译成与当前画面路标对齐的自然语言，这依然是学习到的能力，无法用规则替代。

#### 为什么不能用规则做

- **语义多样性无法穷举**：人行道边界、施工围挡、临时占道在视觉里千变万化，规则系统无法覆盖开放世界的长尾情况；
- **误差对齐需要视觉理解**：高德 waypoint（路口中心、1~5m 误差）与画面语义（人行道内侧）之间的对齐，本质是视觉 grounding 问题，不是坐标变换问题；
- **进度判断需要模型**："当前是否已到达路口""是否该执行右转"这类判断需要理解画面内容，ABot-N0 用 VLAC 的 Critic 模式来做，同样是模型。

#### 规则用在哪

规则并没有消失，而是下沉到**安全层**——那里恰恰需要确定性：

- 地理围栏（禁止进入车行道/水域）、红灯停、速度限制、紧急制动距离；
- 设计原则：**规划必须语义化（模型），安全必须确定性（规则）**。Planner 的输出可以灵活，但任何输出都要经过安全层的硬性过滤。

### 6.5 精修模型的训练 GT 怎么构造

既然语义转换是模型，就需要 (粗路由输入 → 语义指令输出) 的训练对。核心思路：

> **用特权信息（仿真语义地图 / 重建几何）把同一个环境表达两次——一次退化成"高德式"粗路由作为输入，一次精确到路标级语义作为标签。模型学的就是两者之间的转换映射。**

语义方案下只需构造 **B（语义指令）+ C（Critic 评估）** 两类 GT；A 类坐标 GT 已废弃，仅留作对照参考。

#### A. 坐标式子目标 GT：`(dx, dy, θ)`（已废弃，仅作对照）

**仿真自动生成（主力，百万级）：**

```
1. 在 SocCity/城市仿真中取一个智能体位姿 + 当前渲染画面
2. 模拟"高德式"粗路由：
   - 在道路级拓扑上规划全局路径
   - 只保留路口中心点，并注入 1~5m 高斯噪声  ← 模拟真实高德误差
3. 生成 GT 精修结果：
   - 把带噪粗路由投影到人行道导航图上（特权信息）
   - 取前方 5~10m、在当前视野内、位于人行道多边形内的点
   - 用里程计真值换算成相对位姿 (dx, dy, θ)
4. 得到训练对: (噪声粗路由, 画面, 位姿) → (精确人行道子目标)
```

关键在于第 2 步**故意退化输入**——如果输入本身就是精确路由，模型学不到任何修正能力。

**真实数据（重建管线）：**

- 互联网行走视频 / 实采数据 → π3 稠密重建 + MoGe 尺度对齐 + 语义分割出人行道；
- 沿真实 GPS 轨迹调一次高德步行 API，拿到真实粗路由作为输入；
- GT = 重建几何中、人行道分割区域内的前方路径点。

**必须包含的困难样本：**

| 困难样本 | GT 构造 | 学什么 |
|---|---|---|
| 恢复轨迹 | 起点偏出人行道/偏航，GT = 回正子目标 | 偏航纠错 |
| 施工改道 | GT 偏离高德原路由（走临时通道） | 视觉证据 > 地图先验 |
| 高德缺失区域 | 新小区、公园内部无路由，GT 纯视觉生成 | 无地图先验时的兜底 |

#### B. 语义指令 GT（推荐输出形式）

**仿真自动标注：**

1. 沿 GT 路径从语义地图提取路标（路口、斑马线、商铺、红绿灯、盲道）；
2. 模板生成指令："沿人行道前行 → 路口过斑马线 → 右转沿商铺外侧走"；
3. LLM 改写为多样化表达（R2R/RxR 数据的标准做法）。

**真实街景标注 + 一致性过滤：**

- 教师模型（Qwen3-VL / Gemini 级）对"街景 + 粗路由"生成指令；
- **一致性校验防幻觉**：用另一个模型按指令回推路径，或逐里程碑对照真值轨迹——指令里每个路标必须出现在正确位置，只保留对齐的样本（ABot-N0 构造 Object-Goal 推理数据时用的就是这套过滤法，0.1M 高质量样本就是这么筛出来的）。

#### C. Critic（进度/完成评估）GT

VLAC 的 Critic 模式同样需要 GT：

- **仿真**：特权信号直接可用——沿路由的归一化进度、子目标完成 flag、偏航量，零成本；
- **真实**：重建轨迹计算进度增量；教师 VLM 标注 + 一致性过滤。

#### D. 训练方式与规模建议

| 阶段 | 数据 | 方法 |
|---|---|---|
| SFT | (粗路由 → 语义指令) 对，仿真 500K + 真实 100K | 标准指令微调 |
| RL 对齐 | SocCity 闭环 rollout | GRPO，奖励 = 指令执行后子目标落在人行道内 + 沿路由进度 + 不违反交通规则（仿真直接判定） |

规模上 Planner 数据需求远小于 Actor（16.9M 级）：精修是高层语义判断，**50 万~100 万高质量训练对即可起步**，瓶颈在 GT 质量而不是数量——这也是为什么一致性过滤比堆量更重要。

### 6.6 语义指令的四个采集来源

语义方案下有两条数据需求：**Planner 训练对**（高德粗路由 + 视觉观测 → 路标锚定指令）和 **Actor 训练对**（语义指令 + 第一人称观测 → 执行轨迹，沿用 3.3 的 VLN 管线）。语义指令本身按性价比排序有以下来源：

#### 来源 1：高德 API 批量合成（免费的种子数据）

- 在城市内批量采样 (起点, 终点) 对，调高德步行路径规划 API；
- API 返回的 `steps` 数组**自带每段文字指引**（"沿 XX 路向北步行 200 米左转"）——这是现成的粗指令，且是 Planner 输入端的真实分布；
- 局限性：道路级、距离锚定、不区分人行道，**不能直接当训练标签**，只能当输入端；
- 成本：百万级点对只需 API 调用费。

#### 来源 2：仿真路标化转换（主力训练对）

把来源 1 的粗指令"翻译"成路标锚定指令，这一步在仿真里自动完成：

```
高德式粗指令: "沿XX路向北步行200米左转"
        ↓ 在 SocCity 中复现该路由
特权语义地图提取路标序列: [人行道, 便利店, 斑马线, 红绿灯路口]
        ↓ 模板骨架 + LLM 多样化改写
路标锚定指令: "沿人行道经过左手边便利店, 走到红绿灯路口过斑马线左转"
```

一次生成同时产出两种数据：

| 产出 | 用途 |
|---|---|
| (粗指令 + 渲染画面 → 路标化指令) | Planner SFT 训练对 |
| (路标化指令 + 第一人称渲染视频 + 轨迹) | Actor VLN 三元组（教师强制回放） |

#### 来源 3："人听导航"真实采集（最自然的示范数据）

这是语义方案独有的红利——**人类本身就是"听语义指令导航"的完美示范者**：

- 采集员开着高德步行导航走路，头戴/胸前相机录第一人称视频，同步录高德 TTS 播报音频与 GPS 轨迹；
- 事后对齐：播报文本 ↔ 视频时间轴 ↔ 轨迹，直接得到 (指令, 观测, 执行) 三元组；
- 人的执行包含了所有难以仿真的细节：怎么绕临时障碍、怎么在人群中穿行、实际在哪个位置转弯；
- 可众包扩规模；机器人遥操作版本作为动力学分布的补充。

#### 来源 4：互联网视频 + 教师标注（扩规模）

- 第一人称城市行走视频（YouTube/B站/抖音）→ π3 重建 + MoGe 尺度对齐得到轨迹；
- 教师 VLM 看视频 + 轨迹生成语义指令；
- **一致性过滤**：指令里的每个里程碑必须能对上重建轨迹与画面内容，只保留对齐样本（同 6.5 B 的方法）。

#### 指令质量三原则

1. **路标锚定 > 距离锚定**："走到路口左转"优于"走 100 米左转"；
2. **单段复杂度受限**：每条指令 1~2 个动作 + 1 个路标，对应 50~200m 一段——太长的指令 VLA 执行退化；
3. **困难样本显式构造**：偏航恢复、施工改道、无路由区域（同 6.5 A 的困难样本表，改造为指令形式）。

#### 规模配比建议

| 来源 | Planner 训练对 | Actor VLN 三元组 | 成本 |
|---|---|---|---|
| 仿真路标化 | 500K | 800K | 低（全自动） |
| 人听导航实采 | 100K | 150K | 中（众包） |
| 互联网视频 | 200K | 400K | 低（自动 + 教师模型） |
| **合计** | **800K** | **~1.35M** | |

## 十、总结

专注户外长距离导航的技术方案，核心是**"高德深度集成 + 社会合规 + 多层安全"**：

1. **高德不是工具，是系统组件**：POI、路径、路况、围栏深度融入 Planner；
2. **社会合规是户外导航的灵魂**：通过 SAFE-GRPO 让模型学会"人行道优先、斑马线过街、红灯停、礼让行人"；
3. **导盲场景安全冗余必须多层**：地理围栏 → 社会合规 → 实时避障 → 紧急停止 → 人工接管；
4. **数据必须户外导向**：互联网视频、SocCity 仿真、真实街景、高德 POI 缺一不可；
5. **参考"涂涂"产品形态**：四足机器人、全自主、开放环境、导盲优先。
