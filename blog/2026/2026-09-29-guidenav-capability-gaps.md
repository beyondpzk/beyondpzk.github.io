# 从视觉复走到自主巡检：GuideNav 的十项能力扩展

GuideNav 提供了视觉示教复走的基础能力。将它扩展为自主巡检系统，还需要补齐避障、任务动作、报告与地图维护等模块。本文按十项能力分别列出实现选项，再给出由小到大的验证顺序。

以下方案属于工程设计建议，具体取舍取决于场地、传感器与算力条件。整体架构可结合[园区巡检系统设计](/blog/2026/2026-09-29-guidenav-park-patrol)阅读。

## 1. 避障 / 动态障碍

**现状**:零避障,任何估计失败就发零速;导盲场景靠"人握挽具"兜底,巡检把人拿掉后这是第一缺口。

- **A. 几何安全层(最简,先做)** — LiDAR/深度 → 局部 costmap/安全区 → 急停或减速。零改 GuideNav,ROS2 `safety_node` 夹在 `/cmd_vel` 前。出处:Nav2 costmap 思路;硬件 Livox Mid-360 / RPlidar。
- **B. 局部规划器(确定性绕障)** — DWA/TEB(Nav2 / Move Base),需要局部 costmap。优点:能绕不只停;代价:引入规划层、要调参。
- **C. 图像目标 VLA(学习式绕障)** — NoMaD(19M,开源)/ OmniVLA / ViNT 替代 (ρ,α,β) 控制器,扩散/DiT 多模态轨迹可学习绕障行为，仍需独立碰撞检查。对应 [GuideNav 与 VLA 融合：记忆、目标接口与局部执行](/blog/2026/2026-09-29-guidenav-vla-integration) 模式 2。代价:边缘算力、异步。
- **D. 社会导航(人流密集)** — SocialNCE / SocNavBench,在人群中礼貌通过。代价:重,一般园区暂不需要。

**建议**:P0 用 A 保安全底线;想平滑绕障再上 C;B 作确定性兜底;D 暂缓。

## 2. 检查点 / 到点动作

**现状**:只有"走到最后一帧"一个目标,没有到点触发。

- **A. 关键帧打标 + 触发(先做)** — teach 时给关键帧打语义标签("3号门""配电箱"),repeat 到达该节点触发动作(停车/拍照/上传)。关键帧图天然就是检查点列表。
- **B. 事件驱动状态机** — 每个检查点绑定 action 序列(多角度拍照/云台转动/读表/开门信号),状态机编排。
- **C. PTZ 云台多视角采集** — 到点转动云台多角度取证。

**建议**:A + B,检查点动作做成可配置的 per-node action 列表;云台视取证需求。

## 3. 异常检测(业务核心)

**现状**:GuideNav 零感知,巡检的产出物只能外部补。

- **A. 通用目标检测(已知异常)** — YOLO / RT-DETR,检测人/车/车牌/火/烟/异物。成熟、可量化、边缘可跑。
- **B. 变化检测(未知异常)** — 以关键帧为基准图,对比当前帧找差异:帧差/光流(简单)、DINOv2 特征距离、专用变化检测模型。与 VT&R 地图天然契合:基准图就是关键帧。
- **C. 专用识别** — 车牌识别、仪表读数、火/烟检测(有开源模型)。
- **D. VLM 开放式判断** — Qwen-VL 等对可疑画面做"有无异常"问答,兜底无法穷举的异常。

**建议**:A + B 双路(已知 + 未知),关键帧当基准图;B 是巡检相对"固定摄像头监控"的差异化价值;D 做兜底、控制调用频率省成本。

## 4. 多路线 / 目标选择

**现状**:单条 topomap,目标固定为最后一帧。

- **A. 路线库 + 调度器(先做)** — 每条巡检线一条 topomap + 索引,调度器按时间表/任务选择。
- **B. 图搜索 + 语义目标** — 多条单链拼成图(edges.json),VLM 打标关键帧,语言目标 → 检索 → 图搜索(Dijkstra/A*)→ 关键帧序列。LM-Nav 范式。
- **C. 分层导航(全局路由 + 局部 VT&R)** — 全局拓扑路由选线,局部 GuideNav 复走(对应 [户外长距离导航：全局路由、局部策略与数据闭环](/blog/2026/2026-08-03-outdoor-long-range-navigation))。

**建议**:先 A,再 B;跨园区/多楼才需要 C。

## 5. 环线 / 回路

**现状**:单链,不支持闭环和分叉,闭环处 VPR 会出现歧义。

- **A. 拆段(先做)** — 环路拆成若干单链段,每段一条 topomap,调度串起来。零改动。
- **B. 闭环识别** — VPR 时加闭环检测(NetVLAD/词袋),设"起点=终点"判据,处理起点附近 VPR 歧义。
- **C. 真拓扑图** — 单链升级为 edges.json 图 + 图搜索(对应 [GuideNav 源码解读：从示教关键帧到视觉复走](/blog/2026/2026-09-29-guidenav-code-walkthrough) 的 topomap_plus)。

**建议**:A 先跑;需要任意起点/多出口再 C。

## 6. 速度

**现状**:0.15m/s 导盲步速,4Hz 相机驱动,Reloc3r 平移无尺度。

- **A. 调参 + lookahead 加大** — 提高 max_v,lookahead 1→2,子目标更远、控制更平滑。
- **B. 尺度恢复 + 速度规划** — LiDAR 尺度恢复后,有真距离才安全提速。
- **C. 航点跟踪器 + 高频低层控制** — Reloc3r 输出航点,低层 10Hz 跟踪(对应 [GuideNav 与 VLA 融合：记忆、目标接口与局部执行](/blog/2026/2026-09-29-guidenav-vla-integration) 附录 A.5)。

**建议**:先 B 补尺度,再 C 高频低层,最后 A 调参;没尺度就提速是危险的。

## 7. 夜间 / 雨雾

**现状**:纯 RGB,夜间/雨雾下 VPR 和 Reloc3r 都退化。注意 LiDAR 只救夜间避障,救不了夜间视觉定位。

- **A. 限定时段(最诚实,先做)** — 只白天运营。
- **B. 双地图** — 白天一条、夜间一条(或按光照分图),不同时段加载不同地图。
- **C. 红外/热成像相机** — 红外对光照鲁棒,但需重新验证 VPR/Reloc3r 在红外上的表现。
- **D. 夜间 LiDAR 定位模式** — 夜间退回 LiDAR SLAM 定位,白天视觉;放弃纯视觉一致性,代价最大。

**建议**:先 A;要夜间优先 B(成本最低);C/D 视投入。

## 8. 报告定位

**现状**:拓扑定位,无米制坐标。

- **A. 拓扑位置 + 检查点标签(先做)** — 报告用"检查点 + 时间戳 + 照片"。
- **B. teach 记 GPS/RTK 坐标挂关键帧** — 拓扑 + 绝对坐标,简单。
- **C. 局部度量递推** — LiDAR 尺度 + 里程计递推(有累积误差)。
- **D. 视觉重定位到全局度量地图** — 复杂,一般不需要。

**建议**:A 或 B;别上 C/D,除非有硬指标要求米级坐标。

## 9. 语义 / 语言目标("去3号楼")

**现状**:无语义,只知道"像哪一帧"。

- **A. VLM 打标关键帧 + 检索(先做)** — 离线给关键帧打文本标签,语言目标 → 检索 → 目标节点。
- **B. LM-Nav 范式现代化** — CLIP 打标 + 图搜索 + ViNG 执行 → 换成 DINOv3/Qwen-VL 打标 + 图搜索 + GuideNav 执行([GuideNav 与 VLA 融合：记忆、目标接口与局部执行](/blog/2026/2026-09-29-guidenav-vla-integration) 模式 1)。
- **C. 开放词汇 VPR** — CLIP/DINOv3 开放集检索。

**建议**:A 或 B;先离线打标、别在线打标(省算力)。

## 10. 丢失重定位 / 绑架恢复

**现状**:Markov 滤波只抗小误差,大误差(被人搬走)无恢复。

- **A. 全局 VPR 重定位(先做)** — CosPlace 本身是全局检索,信念发散时原地旋转扫描、多帧投票重定位([GuideNav 与 VLA 融合：记忆、目标接口与局部执行](/blog/2026/2026-09-29-guidenav-vla-integration) 附录 A.6 已有)。
- **B. 备用里程计递推** — 短期里程计续命,恢复共视后校准。
- **C. LiDAR scan matching 兜底** — 加 LiDAR 后可做,无先验地图时能力有限。

**建议**:A + B 足够;C 看是否加 LiDAR。

## 附:推荐演进路线(把上面串起来)

- **P0(先跑通一条线)**:缺口 1-A(LiDAR 安全急停)+ 缺口 2-A(检查点打标)。
- **P1(有产出物)**:缺口 3-A/B(目标检测 + 变化检测)+ 缺口 8-A/B(报告定位)。
- **P2(智能与效率)**:缺口 1-C(图像目标 VLA 绕障)+ 缺口 6-B/C(尺度 + 提速)+ 缺口 4-A(路线库)。
- **P3(规模与边界)**:缺口 5-C(图结构)+ 缺口 9-B(语义目标)+ 缺口 7-B(夜间双地图)+ 缺口 10-A/B(丢失恢复)+ 地图更新机制。
