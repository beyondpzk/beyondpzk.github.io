# GeoScaffold 用几何重建训练视觉语言导航

视觉语言模型可以识别门、椅子和走廊，却可能无法稳定判断距离、通路和可通行区域。GeoScaffold 把这些空间信息转成训练目标，让导航模型学习从 RGB 观测形成紧凑的几何潜变量，再用这些潜变量生成动作。

它的关键设计是八个专用几何 query tokens。训练阶段，这些位置的隐藏状态需要重建深度、连通性和可通行性；部署阶段，目标生成器和重建头被移除，query tokens 与混合注意力掩码仍然保留。因此，“训练时使用几何”不等于“推理时完全去掉几何表示”。

> 论文：*GeoScaffold: Learning Compact Geometric Latents via Reconstruction for Efficient Vision-Language Navigation*  
> 作者：Yixuan Jiang、Wentong Li、An Liu 等  
> 版本：2026 年 10 月 arXiv 预印本 v1  
> [论文](https://arxiv.org/abs/2610.02697v1) · [全文](https://arxiv.org/html/2610.02697v1)

## 为什么用重建任务训练空间能力

连续环境 VLN 要求机器人从第一视角图像和语言指令产生动作。论文使用的动作包括前进 25cm、左右转 15° 和停止。即使语义目标相同，障碍物距离、门口宽度和走廊延伸方向不同，也会要求不同动作。

一种常见做法是在推理期间加入深度、点云、地图或几何基础模型。它能直接提供空间信息，但额外编码器、传感器和融合模块会增加部署成本。

GeoScaffold 让模型在训练时预测空间目标，通过辅助损失改变动作预测使用的表示。这个思路成立的关键是：辅助任务学到的几何必须能进入动作解码，不能只让一个旁支重建头单独完成任务。

## 八个 query tokens 承载三种几何目标

每轮流式对话包含当前 RGB、指令及保留的历史。作者在用户输入末尾、动作生成之前插入八个学习 token，将其分成三组。

| 分组 | token 数量 | 重建目标 | 导航含义 |
|---|---:|---|---|
| 深度 | 4 | 100 个离散深度编码 | 物体和场景表面的距离结构 |
| 连通性 | 2 | 二值通路掩码 | 门、走廊、开口等路线延伸位置 |
| 可通行性 | 2 | 二值可通行区域掩码 | 自由空间和地面一类区域 |

三个重建头读取对应 query 的最后一层隐藏状态。四个深度 query 联合预测整个深度编码网格，并非每个 query 只预测一个深度 token。深度编码也不会加入语言词表逐个自回归生成。

连通性和可通行性目标通过 Grounding-DINO 与 SAM 离线生成。这里的“连通性”是第一视角中的通路区域标注，不能直接理解成全局拓扑图；“可通行性”也受这些视觉标注质量影响，并不自动包含机器人本体的动力学约束。

## 混合注意力如何连接几何与动作

普通语言模型使用因果注意力，当前位置只能看到此前位置。但八个 query 都在描述同一个观测，彼此没有天然的先后顺序。

GeoScaffold 允许同一轮的 query tokens 双向互相注意，其余位置仍然遵循因果规则。后续动作 token 可以读取此前 query 的隐藏状态，query 则不能读取未来真实动作。这样既让几何分组交换信息，也维持动作训练所需的因果关系。

从动作生成的角度，可以把流程理解为：

| 阶段 | 输入和输出 |
|---|---|
| 视觉语言编码 | RGB、指令和历史进入导航模型 |
| 几何 query 更新 | 八个位置聚合当前场景结构 |
| 动作解码 | 读取视觉语言上下文与几何隐藏状态 |
| 训练辅助监督 | 从 query 重建空间目标并反向传播 |

部署时前三项仍然存在。节省的主要成本来自移除目标生成器、深度 tokenizer 和重建头；增加 query 本身仍会延长输入序列。

## 两阶段训练与损失函数

第一阶段在导航训练轨迹的归一化深度图上训练一个 0.74M 参数的 VQ-VAE。它把每张深度图编码为 100 个离散索引，码本大小为 128。完成后冻结编码器、解码器和码本。

第二阶段训练导航模型、query embeddings 和重建头。总目标由动作模仿学习与四项几何损失组成：

$$
\mathcal L=\mathcal L_{\mathrm{policy}}
+\lambda_{\mathrm{tok}}\mathcal L_{\mathrm{tok}}
+\lambda_{\mathrm{rec}}\mathcal L_{\mathrm{rec}}
+\lambda_c\mathcal L_c
+\lambda_{\mathrm{tr}}\mathcal L_{\mathrm{tr}}.
$$

深度 token 采用交叉熵分类。另一个深度重建损失将预测的编码分布映射到码本，再通过冻结解码器还原深度图，计算与目标图的误差。冻结解码器仍可把梯度传回导航模型，只是不更新自身参数。两个掩码采用 BCE 与 Dice 的组合。

作者的主要实现以 Qwen3-VL-4B 为骨干，沿用 StreamVLN 的流式上下文配方，每轮解码一个动作。论文报告策略训练约消耗 1500 A100 GPU 小时，VQ-VAE 约 50 GPU 小时。轻量部署并不意味着训练成本很低。

## 实验必须区分训练数据配置

下表来自论文 Table 1，均为 validation-unseen，SR 和 SPL 单位为百分比。

| 训练配置 | R2R-CE SR | R2R-CE SPL | RxR-CE SR | RxR-CE SPL |
|---|---:|---:|---:|---:|
| 仅 R2R-CE 与 RxR-CE | 55.3 | 51.0 | 53.2 | 46.2 |
| 加额外导航数据与 DAgger 等数据 | 64.8 | 60.5 | 59.6 | 52.2 |

两行之间同时改变了数据量，不能把差值全部归因于几何模块。更有解释力的是 Table 2 的配对实验：同一骨干、训练配方和数据下，比较加入几何监督前后。

| 骨干 | 原始 SR | 加 GeoScaffold 的 SR | 提升百分点 |
|---|---:|---:|---:|
| LLaVA-Video-7B | 39.4 | 47.3 | 7.9 |
| Qwen2.5-VL-3B | 46.4 | 51.9 | 5.5 |
| Qwen3-VL-4B | 48.8 | 55.3 | 6.5 |

这些结果在 R2R-CE validation-unseen 上支持跨骨干有效性。它们更适合判断方法贡献，而跨论文排行榜还需要考虑数据、动作接口和实现差异。

## 哪些消融支持几何接口的作用

在完整模型 SR 55.3% 的配置中，移除深度监督降到 51.1%，移除可通行性降到 53.1%，移除连通性降到 52.7%。深度贡献最大，两种通路相关目标提供额外收益。

监督位置也很关键。直接监督图像隐藏状态的 SR 为 43.2%，监督动作隐藏状态为 51.8%，使用专用 query 为 55.3%。只添加 query、不提供重建监督为 47.7%。这说明收益不能简单解释为“多加几个 token”。

另一个有辨别力的实验是在测试时阻断动作对几何潜变量的注意力，权重保持不变：SR 从 55.3% 降到 52.8%。动作确实利用 query 中的信息；阻断后仍高于无 GeoScaffold 的 48.8%，则支持几何训练也改变了骨干自身的表示。

这些消融支持几何信息进入动作生成，但还不能证明模型形成了精确、完整的三维地图。

## 部署结果与适用边界

作者在 RTX 4090 上测得稳态每帧动作推理 81ms；对照 GA-VLN 和 JanusVLN 分别为 750ms 与 1160ms。这个比较同时包含模型规模、上下文处理和几何模块等实现差异，不能作为单独八个 query 的加速比例。

真机采用 Go2 Edu 与 RealSense D435i，仅使用 RGB，并报告可在 Jetson 设备上本地运行。论文展示两条零样本路线，但正文没有提供完整的板端型号、延迟表和大规模真机统计。因此，81ms 应明确归属于 RTX 4090，不能套到 Jetson 上。

几何标签仍是主要风险来源：视觉分割可能把地面标成可通行区域，却没有表达台阶高度、摩擦、坡度和机器人尺寸。训练阶段的场景覆盖、离线标注误差与本体差异都会影响迁移效果。

## 与 StageVLN 的比较及研究启发

[StageVLN](/blog/2026/2026-10-08-stagevln) 通过几何教师特征蒸馏，以及相对朝向、专家路线进度监督改变导航表示；GeoScaffold 则给模型一个可被动作读取的几何 query 接口，并监督它重建具体空间目标。

后续研究可以在同一骨干和数据下比较两种辅助监督，再将可通行性标签改为本体相关目标，例如净空、台阶高度或轮足可达区域。这是实验建议，需要额外标注和跨本体验证。
