# π₀-FAST：用动作压缩加速 VLA 训练，以及它通向 π₀.₅ 的线索

π₀-FAST 最值得关注的地方，是它把一个看似属于模型架构的问题，重新定位到了训练目标的表示上：机器人动作采样得越密，并不意味着每一个离散 token 都提供了更多可学习的信息。先压缩动作，再训练自回归模型，可以显著改变学习效率。

这项工作对应 Karl Pertsch、Kyle Stachowicz 等人的 **FAST: Efficient Action Tokenization for Vision-Language-Action Models**，首次发表于 **2025 年 1 月 16 日**。它早于 2025 年 4 月发布的 π₀.₅，属于 π₀ 的自回归分支；后续 π₀.₅ 的训练吸收了 FAST 的思想。因此，把它理解成“π₀.₅ 的推理加速版本”会弄反技术关系。

还有一个更容易误读的结论：**论文中的最高约 5 倍加速指训练所需 GPU 小时数；原论文的 π₀-FAST 推理反而比 flow-matching π₀ 更慢。**

本文依据 [FAST 原论文 v1](https://arxiv.org/html/2501.09747v1)、[官方项目介绍](https://www.pi.website/research/fast)及官方代码撰写。实验数字均为作者报告，本文没有重新训练或进行机器人实测；代码核对时间为 2026-09-18。原论文采用 CC BY 4.0 许可，以下为中文解读与独立分析。

## 1. 先分清 FAST、FAST+ 和 π₀-FAST

| 名称 | 实际指什么 | 是否能直接根据图像控制机器人 |
| --- | --- | --- |
| FAST | Frequency-space Action Sequence Tokenization，一套动作分词方法 | 不能，它只负责编码与解码动作 |
| FAST+ | 在约 100 万条真实机器人动作片段上训练的通用 FAST tokenizer | 不能，它提供可复用的动作词表 |
| π₀-FAST | 使用 FAST 动作表示、通过自回归方式预测动作的 VLA 策略 | 可以，但需要匹配的策略权重、输入和本体接口 |
| π₀ | 用 flow matching 动作专家生成连续动作的 VLA | 可以 |
| π₀.₅ | 在 π₀ 基础上发展出的开放环境泛化方案，训练中使用离散动作监督，执行低层动作时使用连续动作专家 | 可以；完整论文系统与开源实现的范围需分开看 |

这里的 FAST+ 也不是“更强的 π₀-FAST 策略模型”。一个通用的动作编码器，不等于一个无需适配就能控制所有机器人的通用策略。[FAST §V-C](https://arxiv.org/html/2501.09747v1#S5.SS3)、[π₀.₅ 官方介绍](https://www.pi.website/blog/pi05)

## 2. 为什么高频动作会让 next-token prediction 变难？

设机器人一次预测一个动作块：

$$
A=[a_0,\ldots,a_{H-1}]\in\mathbb{R}^{H\times D},
$$

其中 $H$ 是时间步数，$D$ 是每一步的动作维度。最直接的离散化方法，是把每个标量分别放入一个 bin，再按照时间顺序展开，因此需要大约 $HD$ 个动作 token。

对于一个 50 Hz、14 维的双臂动作空间，一秒动作就是 $50\times14=700$ 个 token。问题不仅是序列长：平滑轨迹中，同一维度相邻时刻的值很接近，量化之后甚至完全相同。

以单个动作维度为例，训练目标可能长这样：

```text
... 121, 121, 121, 122, 122, 122, 122, 123, ...
```

在 teacher forcing 下，模型已经看到了正确的历史动作。仅依赖前面同一维度的数值，就能解释大量目标 token；图像和任务指令提供的条件信息，未必会成为降低损失的最容易路径。低训练损失与正确完成任务之间，因而可能存在明显落差。

原论文用一个插值玩具实验隔离了这一问题：保持底层曲线不变，只提高采样密度，从每条序列 25 个点增加到 800 个点。逐点分箱训练的自回归模型预测逐渐恶化，极端情况下接近重复第一个动作；FAST 则在这些采样密度下保持较好的预测结果。[FAST §IV](https://arxiv.org/html/2501.09747v1#S4)

我的理解是：**动作表示决定了模型把训练预算花在“重复一个已知数值”，还是“预测一段轨迹的新信息”上。** 这是一种学习效率问题，不能简单归结为 Transformer 没能力表示连续控制。

## 3. FAST 的完整链路：归一化 → DCT → 量化 → BPE

![FAST 动作编码与策略推理流程](/images/pi0-fast/pipeline.svg)

上图按论文方法重绘。编码器将整段连续动作变成较短的离散序列；部署时，VLA 预测这个序列，再通过反向流程恢复动作。

### 3.1 归一化：先统一数值尺度

论文把每个动作维度在训练数据中的第 1、第 99 百分位映射到 $-1$ 和 $1$。若对应统计量为 $q_{01,d}$ 和 $q_{99,d}$，一种直接写法是：

$$
\widetilde A_{t,d}
=2\frac{A_{t,d}-q_{01,d}}{q_{99,d}-q_{01,d}}-1.
$$

这样可以减少不同关节、不同物理量之间尺度差异的影响。分位数映射本身并不保证所有离群值都落在 $[-1,1]$；是否裁剪、如何处理常量维度，需要与训练数据管线一致。

这个步骤必须使用训练集统计量。若每个动作块各自归一化，会丢掉幅度和偏置信息；部署时若又换了一套统计量，同一组 token 就可能对应错误的物理动作。

### 3.2 DCT：沿时间轴，把轨迹转换成频率系数

对每个动作维度独立执行 DCT。用与官方实现一致的正交归一化 DCT-II 表示：

$$
C_{k,d}=\alpha_k\sum_{t=0}^{H-1}\widetilde A_{t,d}
\cos\left[\frac{\pi}{H}\left(t+\frac12\right)k\right],
$$

其中 $\alpha_0=1/\sqrt H$，其余 $\alpha_k=\sqrt{2/H}$。

低频系数描述缓慢变化和整体趋势，高频系数描述较快变化。对许多平滑机器人轨迹，能量会集中到较少的系数上。

**DCT 本身不减少维度，也不造成信息损失。** 一个 $H\times D$ 的动作块，转换之后仍然有 $H\times D$ 个系数。它只是让后面的压缩变得容易。

### 3.3 缩放与取整：真正引入有损压缩的地方

FAST 将系数量化为整数：

$$
Q_{k,d}=\operatorname{round}(\gamma C_{k,d}).
$$

较小的系数会变成零。$\gamma$ 越大，量化网格越细，通常重建更精确，但可压缩性下降；$\gamma$ 越小，则更容易得到稀疏系数。

这里按**系数幅值**产生量化效果，并非固定删除某个截止频率以上的所有分量。一个幅值足够大的高频变化仍然可以被保留。

从正交变换可以得到一个直观的误差关系。设逆量化后的系数误差为 $E=Q/\gamma-C$，则在不考虑额外裁剪、编码范围问题和浮点误差时：

$$
\|\widehat A-\widetilde A\|_F^2=\|E\|_F^2,
\qquad
\frac{\|\widehat A-\widetilde A\|_F^2}{HD}
\leq\frac{1}{4\gamma^2}.
$$

这是本文根据正交 DCT 推导的量化误差上界，不是论文给出的闭环性能保证。即使归一化空间的 MSE 很小，抓取、接触切换或夹爪开合的关键时刻仍可能出错。

### 3.4 展平：优先预测所有维度的低频部分

系数按下面的顺序展开：

$$
Q_{0,1},\ldots,Q_{0,D},\;
Q_{1,1},\ldots,Q_{1,D},\;\ldots
$$

也就是先列出所有动作维度的最低频系数，再进入下一个频率。这样，自回归预测先确定整段动作的大体形状，随后逐渐补充细节。论文指出，这种顺序比先预测完某个动作维度的全部频率更有利于稳定执行。

因此，**FAST token 的顺序不是机器人执行动作的时间顺序**。前几个 token 涉及的是整个动作块的频率结构，不能直接当成最早几个可执行动作。

### 3.5 BPE：把大量零和常见系数组合变成短序列

量化之后，系数虽然稀疏，但数组长度仍然是 $HD$。如果直接让 VLA 输出全部整数，模型仍然要预测大量零。

BPE 学习常见的相邻符号组合，并将它们合并为新的 token。它既可以压缩连续的零，也可以合并常见的跨动作维度系数组合。最终得到长度可变的 token 序列：

$$
z_{1:L}=\operatorname{BPE}_{\Phi}(\operatorname{flatten}(Q)).
$$

这里的 $\Phi$ 是学习得到的词表。FAST 不需要训练一个神经编码器—解码器，但仍然需要学习 BPE；“没有额外神经网络”不能说成“完全不需要训练”。

解码则是 BPE 解码、恢复系数矩阵、除以 $\gamma$、IDCT，最后反归一化。**BPE 对送入它的符号串是无损的，整个 FAST 管线由于量化是有损的。** 上述方法与参数定义见 [FAST §V-B](https://arxiv.org/html/2501.09747v1#S5.SS2)，DCT 的具体归一化方式见[官方 tokenizer 源码](https://huggingface.co/physical-intelligence/fast/blob/main/processing_action_tokenizer.py)。

## 4. π₀-FAST 如何接到 VLM 上？

π₀-FAST 使用基于 PaliGemma 的视觉语言骨干。输入包含相机图像、语言指令和机器人本体状态，输出变成 FAST 动作 token。注意 PaliGemma-3B 的名称包含视觉语言整体，而论文讨论自回归解码开销时提到的 2B，是其中的语言模型骨干。

忽略分隔符等实现细节，训练目标可写成：

$$
\mathcal L_{\mathrm{AR}}
=-\mathbb E_{(o,\ell,s,A)}\sum_{i=1}^{L}
\log p_\theta(z_i\mid o,\ell,s,z_{<i}),
\qquad z=\mathcal T_{\mathrm{FAST}}(A).
$$

训练时，正确的前缀 token 已知，各个位置的预测可以通过带因果掩码的一次前向传播并行计算损失；推理时，后一个 token 依赖前一个生成结果，必须逐步解码。这是“训练效率高”和“执行延迟低”不能画等号的直接原因。

官方 openpi 的实现把这个过程拆得很清楚：

| 代码入口 | 职责 | 阅读时值得关注的点 |
| --- | --- | --- |
| `models/tokenizer.py` 的 `FASTTokenizer` | 拼接任务、状态与动作序列，映射动作词表 | 本体状态仍是分箱后的整数文本；FAST 用于输出动作块 |
| `models/pi0_fast.py` 的 `compute_loss` | 计算输出部分的自回归损失 | 观察 token 掩码与 loss 掩码的区别 |
| `models/pi0_fast.py` 的 `sample_actions` | 自回归生成输出 token | 生成结果还需要后处理，才能成为连续动作 |
| FAST 的 `UniversalActionProcessor` | 动作数组与 BPE token 的双向转换 | DCT 沿时间轴进行；解码需要动作维度和 horizon |

`FASTTokenizer` 还负责把 FAST 的 token ID 映射到 PaliGemma 词表尾部的相应位置。独立 tokenizer 返回的 ID，不能不经映射就直接作为 VLM 的标签使用。[openpi tokenizer](https://github.com/Physical-Intelligence/openpi/blob/main/src/openpi/models/tokenizer.py)、[π₀-FAST 模型实现](https://github.com/Physical-Intelligence/openpi/blob/main/src/openpi/models/pi0_fast.py)

## 5. 实验到底证明了什么？

### 5.1 高频数据的压缩收益更明显

原论文 Table I 对比了一秒动作块的平均 token 数，作者说明这些配置具有可比的重建精度：

| 数据集／任务 | 动作维度 | 控制频率 | 逐点分箱 | FAST | token 数压缩比 |
| --- | ---: | ---: | ---: | ---: | ---: |
| BridgeV2 | 7 | 5 Hz | 35 | 20 | 1.75× |
| DROID | 7 | 15 Hz | 105 | 29 | 3.6× |
| Table Bussing | 7 | 20 Hz | 140 | 28 | 5.0× |
| T-Shirt Folding | 14 | 50 Hz | 700 | 53 | 13.2× |

同样是一秒动作，采样频率上升带来的大量重复值被压缩掉了。不过 **13.2× 是 token 数的比值**，不能直接当作整体训练或推理加速倍数；视觉前向、输入 token、批处理和运行时开销也要计入。[FAST Table I](https://arxiv.org/html/2501.09747v1#S6.SS2)

### 5.2 消融说明：DCT 和 BPE 都有价值

论文在六个真实机器人评估场景和一个仿真评估环境上展开实验。它报告逐点分箱在高频的桌面整理、T 恤折叠任务上学习困难；压缩表示改善了训练。FSQ 神经量化基线同样体现了压缩的价值，但 FAST 在部分灵巧任务上表现更好。

去掉 BPE 后，DCT 仍然有帮助，但大量零 token 重新拉长序列，策略效果也下降。另一个实验把 FAST+ 接到修改为多图输入和动作块输出的 OpenVLA 上，同样改善了 T 恤折叠学习。这支持“动作表示的收益可以跨骨干迁移”，而不是只对某个 π₀ 配置有效。[FAST §VI-B、VI-D](https://arxiv.org/html/2501.09747v1#S6)

### 5.3 “5 倍更快”有明确的比较口径

| 结论 | 比较口径 | 不能据此推出什么 |
| --- | --- | --- |
| 约 3 倍更少训练步数 | Table Bussing 的单数据集实验，FAST 达到较高性能所需步数更少 | 每个任务、每一步训练都快 3 倍 |
| 约 5 倍更少 GPU 小时 | 大规模跨本体训练中，π₀-FAST 用约五分之一 GPU 小时达到与比较的 π₀ 相当的任务表现 | 推理也快 5 倍，或数据需求降为五分之一 |
| DROID 语言遵循更好 | 论文中的 DROID 指令条件评估 | 已证明所有自回归策略都比连续动作策略更理解语言 |

论文在超过一万小时量级的机器人数据上验证了扩展性，也在 DROID 未见场景中展示了自然语言条件的零样本操作。这里的“零样本”是指没有在这些测试场景上再微调，并不表示没有使用机器人数据训练。[FAST §VI-E、VI-F](https://arxiv.org/html/2501.09747v1#S6.SS5)

### 5.4 推理速度恰恰是局限

原论文 §VI-E 报告，在 NVIDIA RTX 4090 上预测一秒动作块：

| 方法 | 动作生成路径 | 典型迭代数量 | 论文报告的延迟 |
| --- | --- | --- | --- |
| π₀ | 约 300M 动作专家进行连续动作去噪 | 10 步 | 约 100 ms 以内 |
| π₀-FAST | 约 2B 语言骨干自回归解码 | 约 30–60 个动作 token | 约 750 ms |

π₀-FAST 的每一步解码更重，步骤也更多。FAST 缩短了相对于逐点分箱的序列，但没有消除自回归串行依赖。这组数值来自原论文的实现和测量环境，不是对后续所有优化实现的速度上限。[FAST §VI-E](https://arxiv.org/html/2501.09747v1#S6.SS5)

还要分开三个概念：动作的**采样／执行频率**、策略生成新动作块的**更新频率**、环境变化后产生有效动作的**反应延迟**。一次预测 50 个动作，再以 50 Hz 执行，只说明轨迹足够密；它没有让模型每 20 ms 都重新观察并决策。真实反应时间还受到已承诺动作长度、感知和通信延迟的影响。

## 6. 从 π₀-FAST 到 π₀.₅：训练表示和执行表示可以不同

π₀-FAST 暴露了一个很有价值的取舍：离散动作 token 很适合训练已有 VLM，但逐 token 生成连续控制信号的部署成本较高。后续 π₀.₅ 的路线吸收了这两类表示各自的优势。

2025 年 4 月的 π₀.₅ 工作在预训练中使用 FAST 离散动作及异构任务监督，并在后训练中引入连续动作专家。2025 年 5 月的 **Knowledge Insulation** 工作进一步给出单阶段联合训练方案：VLM 通过离散动作等目标学习表征；动作专家读取这些表征，学习 flow matching，但其梯度被阻断，不回传破坏 VLM 骨干。部署时使用连续动作专家，舍弃离散的低层动作输出路径。[π₀.₅ 论文 §IV-B](https://arxiv.org/html/2504.16054v1#S4.SS2)、[Knowledge Insulation 官方介绍](https://www.pi.website/research/knowledge_insulation)

这里要区分两个版本：原始 π₀.₅ 的训练安排，与后续 π₀.₅＋KI 的单阶段方案，并非完全同一套训练流程。

对我而言，这条演进线最有价值的启示是：**训练时最能提供有效监督的表示，不一定是部署时延迟最低的表示。** 可以用离散目标帮助骨干学习动作相关知识，再用连续动作专家承担低延迟生成，而不必要求一个输出形式同时满足所有目标。

## 7. 官方实现中容易踩的几个坑

### 7.1 论文默认词表与发布的 FAST+ 配置不同

论文单数据集实验使用 $\gamma=10$、BPE vocabulary size 1024。核对发布的 `physical-intelligence/fast` 可见，FAST+ 的 `processor_config.json` 使用 `scale=10`、`vocab_size=2048`、`min_token=-354`。这对应不同配置，不能把论文的 1024 写死到已发布 checkpoint 的数据管线里。[论文 §V-B](https://arxiv.org/html/2501.09747v1#S5.SS2)、[FAST+ 配置](https://huggingface.co/physical-intelligence/fast/blob/main/processor_config.json)

### 7.2 tokenizer 不替你完成动作归一化

官方 `__call__` 从 DCT 开始，因此调用者应先完成归一化。下面仅演示已归一化动作的编解码接口，使用合成的平滑轨迹；它不加载 VLA，也不代表机器人性能复现：

```python
import numpy as np
from transformers import AutoProcessor

tokenizer = AutoProcessor.from_pretrained(
    "physical-intelligence/fast",
    trust_remote_code=True,
)

# [batch, time, action_dim]，这里构造 1 秒、50 Hz、14 维的示意轨迹。
# 真实数据必须采用与策略训练一致的归一化和动作定义。
H, D = 50, 14
t = np.linspace(0, 1, H, endpoint=False)
phase = np.linspace(0, np.pi, D)
actions = (0.5 * np.sin(2 * np.pi * t[:, None] + phase)).astype(np.float32)
actions = actions[None, ...]

tokens = tokenizer(actions)  # list[list[int]]，每个样本长度可以不同
reconstructed = tokenizer.decode(tokens, time_horizon=H, action_dim=D)

print("tokens per chunk:", [len(seq) for seq in tokens])
print("normalized MSE:", float(np.mean((reconstructed - actions) ** 2)))
```

正式实验应固定 tokenizer 的版本及软件环境。特别是策略推理时，tokenizer 可能从未执行过编码，无法依赖之前缓存的 shape；显式传入 `time_horizon` 和 `action_dim` 更清楚。[官方使用说明](https://huggingface.co/physical-intelligence/fast)

### 7.3 有些失败会被转换成零数组

核对源码可见，`decode` 在 token 解码或系数 shape 检查失败时，会打印错误并回退到零系数。编码时还存在 `min_token` 下界处理。因此“BPE 无损”和前面的量化误差推导，都有输入可表示、解码有效的前提。

工程评估中应单独统计解码失败、超长序列截断和越界系数，不要只对成功解码的样本计算平均误差。**归一化后的零动作也不一定等于物理意义上的停止**，这取决于动作参数化与反归一化统计量。[FAST tokenizer 源码](https://huggingface.co/physical-intelligence/fast/blob/main/processing_action_tokenizer.py)

### 7.4 FAST+ 的通用性有两种证据

论文将 FAST+ 在未见机器人数据上的**离线压缩测试**，与使用 tokenizer 训练策略后的**闭环任务测试**分别报告。FAST+ 的训练混合包含部分真实策略评估任务的数据，而 Figure 8 的离线测试使用 tokenizer 未见的数据。

所以，不能把“灵巧手、人形等轨迹也可以压缩”，扩大为“这些本体上的通用闭环策略已经全部验证”。论文将静态机械臂之外的进一步策略验证列为未来工作。[FAST §VI-C、VII](https://arxiv.org/html/2501.09747v1#S6.SS3)

## 8. 对 VLA 和世界模型研究的判断

**我更看重 FAST 作为动作监督接口的价值。** 如果要把高频机器人数据接到预训练 VLM 上，它给出了一个结构简单、可解释、可以先独立检查重建质量的方案；如果目标是动态场景下的快速闭环，仅采用原始 π₀-FAST 的自回归执行路径并不够。

对后续实验，我会优先做三件事：

1. **先建立表示的误差预算。** 在相同动作参数化、horizon 和归一化下，对比逐点分箱、FAST 与学习式 tokenizer，同时看 token 数、重建误差、夹爪切换时刻和接触阶段的误差。
2. **在相同计算预算下比较策略。** 短序列不保证收益来自更好的条件理解，需要同时记录 GPU 小时、任务成功率、语言遵循率和生成延迟，避免只比较训练步数或 token loss。
3. **测试训练与部署分离。** 保留 FAST 离散动作作为骨干的监督目标，让连续动作专家负责执行，再通过消融判断离散监督究竟改善了什么。

对于世界模型，这第三点尤其值得借鉴：训练目标可以为表征学习服务，推理时不一定要完整生成所有训练目标。但 FAST 本身没有证明“未来视频可以省略”，也没有提出基于世界模型的规划；是否保留未来预测分支，需要通过独立的闭环实验判断。

这项工作的长期价值，在于提醒我们检查一个容易忽略的变量：当大模型学不好机器人控制时，除了增大模型和数据，还应检查**每个训练目标究竟携带了多少新的动作信息**。
